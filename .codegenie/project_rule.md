# 代码修改安全规则（Code Modification Safety Rule）

## 核心原则
在修改任何现有代码时，**严禁直接删除或覆盖**原有的错误/旧代码。必须遵循“**先注释留痕，后追加修复**”的流程。

## 强制执行流程
当需要修复 BUG 或重构代码时，必须严格按照以下步骤操作（按顺序）：

1. **定位错误代码块**：确定需要修改的具体行或代码段。
2. **保留原样并注释**：
    - **不要**使用 `Delete` 或移除操作。
    - 将原代码**整行或整段**用注释语法包裹起来。
    - 根据文件后缀自动识别注释语法（如 `.ets/.ts/.js` 使用 `//` 或 `/* */`，`.xml/.html` 使用 `<!-- -->`，`.py` 使用 `#`）。
3. **标注错误原因（必需）**：
    - 在注释的原代码**正上方**或**同行右侧**，使用醒目标记写明废弃/错误原因。
    - 格式必须包含：`【废弃/错误】` + `原因简述` + `（可选：时间戳或修复依据）`。
4. **添加修复代码**：
    - 在注释块的下方，编写新的、正确的、可直接运行的代码。
    - **禁止**在原行直接修改导致 git diff 无法追溯原始逻辑。

## 特殊场景补充
- **如果改动涉及大量代码（超过 20 行）**：允许只保留头尾各 2 行作为上下文标记，中间用 `// ... 此处代码已弃用，详见下方修复 ...` 替代，但在修复区域必须完整写出新逻辑。
- **纯新增功能（不涉及旧逻辑）**：不受此规则限制，直接追加新代码即可。

## 违规纠正
如果我（用户）发现你直接覆盖/删除了旧代码而未注释，我将会回滚你的更改，并要求你重做。请优先考虑代码的可追溯性。
