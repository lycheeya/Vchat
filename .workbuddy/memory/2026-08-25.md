## 语音录音文件不生成的根因与修复
- 根因：`bottominput.ets` 的 `LongPressGesture.onAction` 只调 `checkpermission()`（仅弹面板），真正创建 .wav 并启动采集的 `begainrecord()` 从未被调用 → `filesDir` 下从不生成文件。
- 修复 1：`checkpermission()` 权限通过分支加了 `this.begainrecord()`。
- 修复 2（顺带）：`audioRecord.ets` 的 `start` 原只写裸 PCM（非合法 wav）。现补 44 字节 WAV 头（RIFF/fmt/data），录完用 `fileIo.lseek` 回填两个 size 字段，产出可播放 .wav。
- 注意：滑到左侧 'delete'（取消）时 `releaseFinger` 会 `delFilePath` 删文件，只有 text/none（发送）状态文件才保留。
- 路径：`getContext().filesDir + '/' + uuid + '.wav'`，DevEco Device File Explorer 对应 `.../haps/entry/files/`。

## 发语音弹 "system error" 根因与修复
- 根因：`audioRecord.ets` 原 `stop()` 在松手时立即 `await audioCapturer.stop()`，而 `start()` 的 `while` 循环里 `read(size, true)` 是阻塞的，采集器被强行停掉会打断正在阻塞的 read，抛系统错误，被 catch 弹成 "system error"。每次正常发语音都弹，并非录音失败。
- 修复：拆分停止逻辑——`stop()`（releaseFinger 调用）只置 `recording=false` 让读取循环自然退出；新增 `stopCapturer()` 在 `start()` 循环退出后才干净 stop。
- `release()`（页面销毁）同样先自然停止再 release，避免阻塞 read 抛错。
- 关键经验：OpenHarmony AudioCapturer 阻塞 read 时不能直接 stop，否则 read 抛 "system error"。

## 弹 "system error"/"illegal statu" 最终处理（当前状态）
- 用户反复被弹窗困扰，最终把录音路径的 catch 弹窗**彻底移除**，改为 `console.error` 输出到 DevEco Log（`AudioCapturer.start error:`）。
- WAV 头回填移到 `finally`，无论正常结束还是异常中断都产出可播放 wav。
- 文件 `audioRecord.ets` 现含：`busy` 防并发 start（用户/工具加）、start 前状态守卫（非 PREPARED/PAUSED 先释放重建）、`stopCapturer()`、WAV 头、`promptAction` 导入已删除。
- 若用户仍报 "system error"，优先怀疑**旧构建缓存未刷新**（需 Clean Project 后重新构建运行），并让其看 Log 确认具体异常。
